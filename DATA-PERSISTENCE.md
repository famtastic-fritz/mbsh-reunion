# Data Persistence — MBSH v2

Schema, security, dev/prod boundary, secrets strategy.

## Architecture

Hybrid: Netlify (frontend) + GoDaddy cPanel (PHP/MariaDB backend) + Resend (transactional email). Same as canonical.

## Schema (10 tables, utf8mb4, idempotent)

`rsvps` · `sponsors_pending` · `sponsors_approved` (FK → pending) · `memories` · `in_memory` · `time_capsules` · `chatbot_questions` · `rate_limits` · `admin_login_attempts` · `admin_audit_log`

All `CREATE TABLE IF NOT EXISTS` — re-applying is safe.

Apply via `bash scripts/setup-mbsh-backend.sh` (Phase 4 SSH apply, replaces phpMyAdmin paste).

## Dev / prod boundary

**Dev never connects to prod.** Local dev DB is a separate database (`mbsh_reunion_v2_dev`), separate user, mode-0600 `.env` at repo root. Production secrets live ONLY on the GoDaddy server at `/home/nineoo/.config/mbsh-config.php` (mode 0600, OUTSIDE web root). The setup script enforces this — never writes prod credentials to the dev box.

## Form submission flow

```
Browser POST → CORS check (origin allow-list + Netlify regex pattern) →
  Content-Type validation (JSON for json endpoints, multipart for upload endpoints) →
  honeypot field check (silent reject) →
  form-load timestamp check (silent reject if <3s) →
  rate-limit check (rate_limits table, per IP per endpoint) →
  input validation (lib/validate.php; required/email/enum/length, server-side only) →
  file upload safety if applicable (lib/upload.php; finfo + size + dimensions + UUID rename + SVG reject) →
  PDO INSERT (prepared statement, parameter binding) →
  Resend notification (committee + classmate confirmation where applicable) →
  success JSON
```

## Production secrets (`/home/nineoo/.config/mbsh-config.php`, mode 0600)

Generated by `scripts/setup-mbsh-backend.sh`. Contains:
- `db_*` — MariaDB credentials (production user)
- `resend_*` — API key + sender addresses (`noreply`, `committee`, `harry` all on `send.mbsh96reunion.com`)
- `allowed_origins` + `allowed_origin_patterns` — Netlify production + branch preview URLs
- `admin_password_hash` (bcrypt via PHP `password_hash`)
- `admin_csrf_secret` (32-byte hex, for HMAC tokens)
- `pending_uploads_path` + `approved_uploads_path` — both under `/home/nineoo/`, pending OUTSIDE web root

## File uploads

- **Pending** (sponsor logos, memory photos) → `/home/nineoo/uploads-pending/{sponsors,memories}/<uuid>.<ext>` — OUTSIDE web root, served only via auth-gated `admin/serve-pending-upload.php`.
- **Approved** → `/home/nineoo/public_html/uploads/approved/{sponsors,memories}/<uuid>.<ext>` — web-accessible with `.htaccess` hardening (deny PHP exec, deny non-image extensions, nosniff).
- MIME validated via `finfo_file()` against allowlist `[image/jpeg, image/png, image/webp]`. SVG explicitly rejected (security: SVG can carry executable JavaScript).

## Admin auth

- Session cookie: `mbsh_admin`, HttpOnly + Secure + SameSite=Strict
- Password verified against `password_hash()` (bcrypt) stored in production secrets
- Login throttle: 5 fails in 15 min → 1 hour lockout (`admin_login_attempts` table)
- CSRF: HMAC tokens (`session_id|expires|sig` base64-encoded), required on every state-change POST
- All admin actions logged to `admin_audit_log` (action, target_table+id, IP, timestamp)
- 4-hour inactivity timeout
- NEVER auth tokens via URL parameters
